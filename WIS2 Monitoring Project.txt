WIS2 Monitoring Events — Complete Project Documentation
========================================================


1. PROJECT OVERVIEW
-------------------
Framework: Django 6.0.6 (Python 3.13.7)
Database: PostgreSQL (wis2_alerts)
Ingestion: Standalone MQTT-to-PostgreSQL pipeline (wis2_ingestion.py)
Auth: Django built-in auth with custom RBAC (Admin / Agent roles)
Theme: Dark/Light mode, custom CSS (no Bootstrap/Tailwind)
Fonts: Space Grotesk (display), Inter (body), JetBrains Mono (code)
Zoom: 0.9 applied globally for size reduction


2. MODELS (telemetry/models.py)
--------------------------------

2.1 Node (managed=False, db_table=nodes)
    - name:              CharField(255), PK — WIS2 Centre identifier (e.g. uk-metoffice-wmc)
    - responsibles:      M2M -> NodeResponsible through NodeResponsibleMapping

2.2 NodeResponsible (managed=False, db_table=node_responsibles)
    - id:                AutoField, PK
    - name:              CharField(255) — Contact name
    - email:             EmailField, unique — Contact email
    - created_at:        DateTimeField, auto_now_add

2.3 NodeResponsibleMapping (managed=False, db_table=node_responsible_mapping)
    - id:                AutoField, PK
    - node:              FK -> Node (db_column=node_name)
    - responsible:       FK -> NodeResponsible (db_column=responsible_id)
    - assigned_at:       DateTimeField, auto_now_add
    - Meta: unique_together = [('node', 'responsible')]

2.4 Alert (managed=False, db_table=alerts, ordering=['-event_time'])
    - id:                UUIDField, PK — From CloudEvents id
    - specversion:       CharField(10) — e.g. "1.0"
    - event_type:        CharField(255) — e.g. "int.wmo.wis.wme.event"
    - source:            CharField(255) — The monitoring service that detected the issue
    - node:              FK -> Node (db_column=node) — The observed WIS2 node
    - event_time:        DateTimeField — When the WME event occurred
    - datacontenttype:   CharField(100) — e.g. "application/json"
    - dataschema:        TextField, nullable — URL of JSON schema
    - conforms_to:       JSONField, nullable — Array of spec conformance URIs
    - severity:          CharField(50) — CRITICAL / ERROR / WARNING / INFO
    - subtype:           CharField(100), nullable — e.g. "gm-alert"
    - channel:           TextField, nullable — WIS2 data channel URI
    - title:             TextField, nullable — Original WME content title
    - display_title:     TextField, nullable — Computed human-readable title
    - description:       TextField, nullable — Full text description
    - wnm:               JSONField, nullable — WIS2 Notification Message payload
    - errors:            JSONField, nullable — Error objects array
    - tests:             JSONField, nullable — ETS test results array
    - summary:           JSONField, nullable — Aggregated test counts dict
    - links:             JSONField, nullable — Link objects array
    - ingested_at:       DateTimeField, auto_now_add — DB insertion timestamp
    - incident_hash:     TextField, nullable — SHA-256 of "{title}:{node}"

2.5 Profile (managed=False)
    - user:              OneToOneField -> auth.User
    - allowed_nodes:     M2M -> Node, blank — RBAC node scoping for Agents

2.6 IncidentEvent (managed=True, db_table=incident_events, ordering=['created_at'])
    - id:                BigAutoField, PK
    - incident_hash:     TextField, db_index — Groups related alerts
    - alert:             FK -> Alert, nullable, db_constraint=False
    - user:              FK -> User
    - event_type:        CharField(20), choices — comment / email_sent / note_added /
                                        note_removed / muted / unmuted / viewed
    - text:              TextField, blank, default='' — Content of the event
    - created_at:        DateTimeField, auto_now_add
    - expires_at:        DateTimeField, nullable — For timed notes
    - active:            BooleanField, default=True — Soft-delete for notes

2.7 IncidentMute (managed=True, db_table=incident_mutes)
    - id:                BigAutoField, PK
    - incident_hash:     TextField
    - user:              FK -> User
    - muted_until:       DateTimeField
    - Meta: unique_together = [('incident_hash', 'user')]

2.8 AlertRetentionPolicy (managed=True, db_table=alert_retention_policy) — singleton TTL setting
    - id:                AutoField, PK (singleton row, id=1)
    - ttl_active:        BooleanField, default=False — Master switch. False = persistence
                         (keep alerts forever); True = purge by retention_days
    - retention_days:    PositiveIntegerField, nullable — Alerts older than this many
                         days (by ingested_at) are purged. Required when ttl_active=True.
                         MinValueValidator(1). Ignored while ttl_active=False.
    - updated_at:        DateTimeField, auto_now
    - clean():           Raises ValidationError if ttl_active=True with no retention_days
    - load():            classmethod — get_or_create the singleton row
    - get_retention_days(): module helper in telemetry/models.py — returns retention_days
                         only when ttl_active=True and days set; otherwise None

2.9 Signals
    - post_save on User -> create_user_profile(): Auto-creates Profile on user creation
    - m2m_changed on User.groups -> sync_staff_on_group_change(): When a user is
      added/removed from the Admin group, is_staff is synced automatically


3. VIEWS (telemetry/views.py)
------------------------------

3.1 Helper Functions
    get_alerts_for_user(user)     Returns Alert.objects.all() for Admin, scoped
                                  Alert.objects.filter(node__in=profile.allowed_nodes)
                                  for Agent, Alert.objects.none() otherwise

    exclude_muted(qs, user)       Excludes alerts whose incident_hash is in the
                                  user's active IncidentMute records

    parse_filter_params(request)  Extracts multi-value GET params: severity, node,
                                  type, alert, source, time_from, time_to,
                                  sort (default: ingested_at)

    apply_filters(qs, params)     Applies all filter params to a queryset

    get_cached_choices(key, qs)   60-second LocMem cache for filter dropdown options

    get_node_choices(user)        Admin: all nodes; Agent: only allowed nodes
    get_type_choices()            Distinct event_type values (max 500)
    get_source_choices()          Distinct source values
    get_alert_choices()           Distinct display_title values (max 500)

3.2 View Functions

    dashboard (login_required) -> telemetry/dashboard.html
        Time window filtering: ?window=all|12h|24h|custom&from=YYYY-MM-DDTHH:MM&to=YYYY-MM-DDTHH:MM
        Context:
            severity_counts      dict {CRITICAL: N, ERROR: N, WARNING: N, INFO: N}
            mini_alerts          Latest 20 alerts by ingested_at
            critical_alerts      Latest 20 CRITICAL alerts
            type_choices         All distinct event_types
            node_choices         Node names (scoped to user)
            source_choices       All distinct sources
            ets_data             Latest ETS report per node with summary stats
            time_window          Current time window setting
            window_from / window_to   Custom window bounds (datetime-local values)

    monitor_alerts (login_required) -> telemetry/alert_list.html
        Applies all filters, excludes muted, orders by sort, paginates (10/page).
        Context:
            alerts               Current page of alert objects
            page_obj             Django paginator page object
            latest_ingested_iso  Max ingested_at for polling
            base_query           URL query string without page
            type_choices / node_choices / source_choices / alert_choices
            current_severities / current_nodes / current_types / current_alerts /
                current_sources  Currently selected filter values
            current_time_from / current_time_to       Currently selected time range
            current_sort         event_time or ingested_at

    api_alerts (login_required) -> JSON
        GET params: since, offset, limit (default 50), all filter params
        Returns: {alerts: [{id, event_type, severity, source, node, node_id, title,
                  display_title, description, event_time, subtype,
                  ingested_at}], count: N}

    api_alerts_per_day (login_required) -> JSON
        GET params: days (7/14/30), node[], group_by (severity/event_type)
        Returns: {labels: [date strings], datasets: [{label, data, borderColor, ...}]}
                 Used by Chart.js line chart

    alert_detail (login_required) -> telemetry/detail.html
        Loads alert, parses tests (list or dict) and summary, queries node history
        (paginated, 6/page), loads node responsibles, records a viewed event
        (rate-limited to once per 5 minutes).
        Context:
            alert                Full alert object
            tests_list           Normalized test results
            summary_dict         Test result counts
            history_page_obj     Paginated alerts for same node
            history_count        Total history alerts count
            node_responsibles    People responsible for this node

    alert_search (login_required) -> JSON {found: bool, count: int}
        Keyword search across alert text fields and JSON blob

    incident_comment (POST, login_required) -> JSON {id, created_at}
        Creates an IncidentEvent with event_type='comment'

    incident_note (POST, login_required) -> JSON {id, expires_at}
        Creates a timed note (event_type='note_added') with duration in seconds

    incident_note_remove (POST, login_required) -> JSON {success: true}
        Soft-deletes a note (sets active=False), creates note_removed event

    incident_mute (POST, login_required) -> JSON {muted_until}
        Creates/updates IncidentMute, creates muted event

    incident_unmute (POST, login_required) -> JSON {success: true}
        Deletes IncidentMute, creates unmuted and comment events

    incident_activity (login_required) -> JSON
        Returns: {events: [{id, event_type, text, user, user_full, created_at,
                  expires_at, active}], notes: [...], muted_until: str|null,
                  total, offset, limit}

    email_responsible (POST, login_required) -> JSON {success: true}
        Sends email via Gmail SMTP to a responsible person with full alert details.
        Creates email_sent event.

    account_view (login_required) -> telemetry/account.html
        Context: username, full_name, email, allowed_nodes, is_admin

    alarms_catalogue (login_required) -> telemetry/catalogue.html
        No context data — pure static documentation page.

    alert_history_fragment (login_required) -> telemetry/history_fragment.html
        AJAX fragment for paginated node history (6 per page). Returns HTML.

7. INGESTION PIPELINE (wis2_ingestion.py)
-------------------------------------------

7.1 Configuration
    Broker:       globalbroker.meteo.fr:443 via WebSocket (/mqtt)
    Auth:         everyone/everyone
    Topic:        monitor/a/wis2/#
    DB:           PostgreSQL wis2_alerts, user wis2_admin
    Batch:        250 records, 5-second flush interval
    Reconnect:    5s delay, max 10 attempts

7.2 Message Flow
    1. MQTT on_message -> JSON decode -> parse_wmem_record() -> queue
    2. db_writer_worker thread -> batch INSERT ... ON CONFLICT (id) DO NOTHING
    3. Auto-creates missing nodes on ForeignKeyViolation

7.3 parse_wmem_record(payload_json) — Field Extraction
    Extracts from CloudEvents structure:
      Top-level: id, specversion, type, source, subject->node, time->event_time,
                 datacontenttype, dataschema
      data.:     conformsTo, severity, subtype, links
      data.content.: channel, title, description, wnm, errors, tests, summary, links
    Computes: display_title, incident_hash

7.4 _compute_display_title(title, description) — Display Title Rules (19 patterns)
    "Template:" in title                    -> "Maintenance: Template Notice"
    "un-wmo-global-test" in title           -> "Maintenance: Test System"
    "CMA Global Monitor" in title           -> "Maintenance: CMA Global Monitor"
    "CMA Global Services" in title          -> "Maintenance: CMA Global Services"
    "CMA Global Broker" in title            -> "Maintenance: CMA Global Broker"
    "GISC Beijing" in title                 -> "Maintenance: GISC Beijing"
    "DWD Service" in title                  -> "Maintenance: DWD Services"
    "maintenance" (case-insensitive)        -> "Maintenance: General"
    "context deadline exceeded" in desc     -> "Timeout: context deadline exceeded"
    "unexpected EOF" in desc                -> "Network Termination: unexpected EOF"
    "GOAWAY" in desc                        -> "Network Termination: server sent GOAWAY"
    "client connection lost" in desc        -> "Network Termination: client connection lost"
    "connection refused" in desc            -> "Connection Refused"
    "HTTP status 502" in desc               -> "HTTP Error: 502 Bad Gateway"
    "HTTP status 403" in desc               -> "HTTP Error: 403 Forbidden"
    "expected a valid start token" in desc  -> "Invalid Response"
    "connection reset by peer" in desc      -> "Network Termination: connection reset by peer"
    "i/o timeout" in desc                   -> "Timeout: i/o timeout"
    Title starts with "Target" + "is down"  -> "Target is down"
    No pattern matched                      -> Raw title as-is

7.5 DB Writer Thread
    Batches up to 250 records, flushes every 5s or when queue is empty
    ON CONFLICT (id) DO NOTHING for idempotent inserts
    Auto-creates missing nodes on FK violation (regex extracts node name from error)
    Handles reconnection on OperationalError/InterfaceError

8.5 ALERT RETENTION (TTL)
---------------------------

    Config (admin panel):  Alert retention policy -> ttl_active (master switch) and
                           retention_days (days). TTL off = persistence (default),
                           days ignored. TTL on = purge by days (days required).

    Basis:                 alerts.ingested_at < now - retention_days
                           (uses idx_wgt_ingested_at)

    Command:               python manage.py purge_alerts
                           --dry-run   preview only, no deletes
                           --days N    override configured days for this run
                           --limit N   cap total alerts purged
                           Batches of 5000, transaction per batch

    Cascade:               Deletes incident_events (history) tied to purged
                           alerts first (FK db_constraint=False, so no DB
                           cascade); keeps incident_mutes (hash-keyed)

    Scheduling:            In-app scheduler inside the ingestion process
                           (wis2-ingestion), nightly at 03:00 server time.
                           Runs the purge_alerts command from a dedicated
                           "Purge-Scheduler" daemon thread (telemetry/purge_scheduler.py).
                           No systemd timer / external scheduler required.
                           Env vars: PURGE_HOUR (default 3), PURGE_ON_STARTUP
                           (default false). Restart wis2-ingestion to apply.
                           Manual run: python manage.py purge_alerts

11. CROSS-CUTTING FEATURES
----------------------------

    RBAC:                  Admin sees all alerts; Agent sees only alerts for
                           their allowed_nodes

    Live Polling:          5-second intervals on dashboard and monitor pages,
                           inserting new items with animations

    Dark/Light Theme:      localStorage-persisted, full CSS variable system,
                           affects charts and scrollbars

    Client-Side Filtering: Live feed filters items without server round-trip;
                           monitor page cascades filter options via API

    Incident Collaboration: Comments, timed notes (banner), muting (user-scoped),
                           email notifications, activity timeline, auto-logged
                           page views

    Find Alert:            Global keyword search in header of all pages, checks
                           via /api/alert-search/ then redirects to the monitor
                           alerts page with the keyword filter applied

    Responsive:            Grid collapses at 640px/768px/1000px/1100px breakpoints

    Accessibility:         prefers-reduced-motion disables animations,
                           focus-visible outlines, semantic HTML

    Documentation:         Comprehensive WIS2 alert reference page with 13 sections
                           covering infrastructure analysis, schema validation,
                           response framework, and all alert fields
